# Hermes Collab Protocol — Stress Test Repo

## Overview

This repository exercises **every capability** of the Hermes Collab Protocol.
Multiple agents on different devices claim issues, work on feature branches, create PRs,
and coordinate — all on `develop`, never on `main`.

## Team

| Device | Agent | Role | Capabilities |
|--------|-------|------|-------------|
| windows-main | hermes | lead | all, python, typescript, docs, docker, ci, testing, cli |
| macbook-pro | opencode | contributor | python, typescript, docs |
| linux-server | codex | contributor | python, docker, ci, testing |

## Work Division

- [ ] **#1 — Project scaffold** (setup, docs) — Initial project structure
- [ ] **#2 — Python core library** (python, core) — `hermes_test` package
- [ ] **#3 — CLI interface** (python, cli) — `cli.py` command-line tool
- [ ] **#4 — GitHub Actions CI** (ci) — `.github/workflows/ci.yml`
- [ ] **#5 — Unit test suite** (testing, python) — `tests/` with pytest
- [ ] **#6 — TypeScript config** (typescript) — `config/` with TS configs
- [ ] **#7 — Documentation site** (docs) — `docs/` with MkDocs
- [ ] **#8 — Docker setup** (docker) — `Dockerfile` + `docker-compose.yml`

## Communication Channels

- State file: `.hermes-state.json` (git-tracked)
- GitHub Issues: Task tracking
- GitHub Discussions: Coordination
- GitHub Projects: Visual task board

## Rules

- Never commit to `main` directly
- All work on `develop` branch
- Feature branches: `feature/{issue-number}-{short-description}`
- PRs reviewed by another device before merging
- Update `.hermes-state.json` after each session
- Commit messages include `device:` metadata
- Max 2 parallel tasks per device

## Onboarding

1. Clone repo
2. `project-collab.py bootstrap` (download script)
3. `project-collab.py init`
4. `project-collab.py pull`
5. `project-collab.py claim <number>`
6. `project-collab.py work`
